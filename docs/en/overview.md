# QA Practice System – Overview

Welcome to the QA practice system.

This project simulates a real-world backend system where requirements, documentation, and implementation may not always be perfectly aligned.

Your goal is to:
- Understand the system behavior
- Validate API functionality
- Verify data consistency
- Identify and report issues

---

## 📌 Scope

This is a simple Task Management System with the following modules:

- Authentication (register, login)
- Project management
- Task management

---

## 📚 Available Documents

You are provided with the following materials:

### 1. API Specification
👉 See: `./api-spec.md`

Contains:
- List of endpoints
- Request/response examples
- Expected behaviors

### 2. Jira Tickets
👉 See: `./jira-tickets.md`

Contains:
- Feature descriptions
- Business requirements
- Expected use cases

---

## 🧪 Your Tasks

As a QA engineer, you should:

1. Review the Jira tickets to understand requirements
2. Use the API specification to explore endpoints
3. Test APIs using Postman or a similar tool
4. Validate data directly in the database (PostgreSQL)
5. Identify inconsistencies, bugs, or unexpected behaviors
6. Write clear and reproducible bug reports

---

## ⚠️ Important Notes

- Not all documents are guaranteed to be correct or complete
- Some behaviors may differ from what is documented
- You may need to cross-reference multiple sources to determine expected behavior

---

## 🎯 Goal

The objective of this exercise is to simulate real-world QA work, where:
- Requirements can be unclear or incomplete
- Documentation may be outdated or inconsistent
- Systems may contain hidden issues

Focus on:
- Critical thinking
- Careful validation
- Clear, professional communication

---

Good luck! 🚀
